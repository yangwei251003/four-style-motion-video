# 代码制作与时间轴

## 写镜头状态和事件

先列每段的观众问题、场景和主体、起始状态、动作、结果、连接物、阅读时间。试渲最容易暴露问题的状态，通常是运动中段、接触附近和最密的一屏。按题材选现有的帧驱动工具，例如 Canvas/Pillow、Remotion、Manim 或 HTML 渲染。保留代码、时间轴及独立音轨，方便局部返修。

| 时间或帧 | 画面状态 | 音频对应 |
| --- | --- | --- |
| 帧 36–61 | 硬物接近表面，速度变化 | 由轻到明显的气流，接触之前仅有移动声 |
| 帧 62 | 硬物第一次接触表面，涟漪或回弹被触发 | 瞬态对准接触帧，音色由两种材料和力度决定 |
| 帧 63–89 | 余振、波纹或碎片向外传递 | 较弱的材质衰减，可延续到下一镜 |
| 帧 92 | 已发生的动作使计数进一 | 短 UI 确认，可与先前的实际碰撞分开 |

一条事件记录包括 `id`、`shot`、`frame`、`kind`、`action`，持续动作另记 `end_frame`。声音需要记录轨道、源素材片段和起音、增益、声像、淡入淡出。镜头级标注静止、预备、接触、余振等可查状态。导出画面和音频时从同一事件表读。

帧驱动示例按整数帧和固定种子取值。粒子位置从年龄、速度和加速度计算，避免渲染先后改变随机结果。语义字幕用帧区间安排出现和留读。真实素材从其 PTS 对齐；遇到掉帧、可变帧率或裁切先校验时间映射。固定帧率下音频位置用 `round(frame * sample_rate / fps)`，避免反复累加浮点时间。外部素材先缓存、校验、记录来源。

## 分层与清晰度

- **原创画面。** 在最终尺寸绘制字形和边缘，像素素材采用整数网格。背景纹理、主体、辅助运动、字幕独立控制。根据目标屏幕缩放检查最小字号和图形边缘。关键运动用前、中、后三个状态同时校验轨迹、遮挡和因果。
- **已有参考或复刻项目。** 先比实际可访问的更高质量来源，查同作品、时长、时序和帧内容。高速转动、变形和字幕交替容易产生光流混叠。复查这些帧的高频细节，必要时在同一时间补状态或在原创成片中直接重绘关键层。输出像素尺寸与实际取得的源分辨率分别记录。
- **节奏。** 先安排镜头的预期、动作和结果，再增加副运动。相邻镜头可用共同的轮廓、方向、光点、道具或数值衔接。移动快时留一个清楚的对象给观众追踪，收束处给字幕和结果足够停留。

## 运行最小示例

[演示脚本](../scripts/render_examples.py) 用 Pillow 和 FFmpeg，从整数帧绘制四类画面，并生成相同起点和长度的 48 kHz 动作、氛围和合成音轨。运行命令、依赖与预览见[安装说明](../README.md)。可将画面函数替换为项目对应的绘制入口，把声音事件换成音效库素材，复用帧到采样点的映射。

这些示例使用原创几何、图形和程序声音。训练重点是机制、时序和验收。完整片需要为故事追加情境、镜头尺度变化、材质层次、适配的音效实录与连续看听评审。
